# Garant-ПО v6.0 — технический промт на исправление

**Роль:** старший инженер Windows/.NET, разработчик локальных приложений и тестировщик. Не считать исправление выполненным только потому, что BAT завершился с кодом 0.

**Исходные факты:** у v5.2 сканирование возвращало 0 устройств и завершалось, но браузер показывал «Подключение» и не получал последующее состояние. Предыдущие версии иногда устанавливали драйверы успешно при зависшем GUI. Windows 10/11 x64; VPN может влиять на внешний DRP, но не должен влиять на обмен с 127.0.0.1.

**Архитектура:** отделить UI-сервер от PowerShell-установщика. Использовать многопоточную обработку HTTP, не блокировать /api/status, /api/events, /api/diagnostics или /api/health длительной операцией. Worker работает отдельным процессом и атомарно сохраняет JSON; GUI только читает его. Протокол обновления состояния: SSE EventSource, с резервным не перекрывающимся опросом. При сетевой ошибке не выдавать ложный итог и не терять последнее корректное состояние.

**Функции:** сканировать устройства Code 28 и Microsoft Basic Display Adapter, показывать имя/HardwareID; драйверы искать по заранее проверенным прямым ссылкам и по DRP при доступности; скачивать с поддержкой прокси и докачки; показывать файл, байты, проценты при известном полном объёме, скорость, этап (поиск/скачивание/распаковка/установка/проверка); проверять содержимое ZIP и точное совпадение HardwareID в INF, устанавливать PnPUtil, повторно сканировать. Не выдавать «драйверы актуальны» до завершения хотя бы одного реального сканирования. Ноль проблемных устройств -> «Все необходимые драйверы установлены. Проблемных устройств не обнаружено»; отсутствие проблем не означает наличие самых новых версий каждого драйвера.

**Кнопки:** каждая кнопка выполняет реальный запрос с подтверждением и обработкой 409; уже выполняемая операция не должна запускаться дважды. Сканирование доступно повторно. «Скачать и установить» при пустом списке делает новую проверку и отображает отсутствие задач, а не крутит индикатор. Кнопка диагностики работает даже во время длительной операции. Экспорт интерфейсных ошибок также доступен локально в браузере при недоступном сервере. Закрытие не должно уничтожить работающий worker без явного действия.

**Устойчивость:** HTTP-сервер привязать строго к 127.0.0.1; POST защищать одноразовым токеном; не слушать внешние адреса. SSE отправлять из отдельного потока. Не допускать XSS в карточках устройств, не запускать произвольные URL и не устанавливать несовпадающий INF. Все ошибки C#, PowerShell, PnPUtil и загрузчика писать в текстовые логи. Диагностический ZIP содержит актуальные файлы UI, сервера, worker и статуса и не включает скачанные драйверы.

**Обязательные тесты:** (1) начальная загрузка интерфейса, (2) сканирование с 0 устройствами, (3) сканирование с 3 устройствами, (4) установка с промежуточным прогрессом, (5) завершение с 0 оставшихся, (6) параллельное скачивание диагностики при установке, (7) повторный запуск/повторная установка с 0 задачами, (8) отказ DRP/отсутствие VPN с понятной ошибкой, (9) закрытие вкладки и повторное подключение, (10) отсутствующий/поврежденный JSON, (11) конкурентные запросы. JS проверять синтаксически и в браузере; C# компилировать на Windows PowerShell 5.1; запуск установки драйверов обязательно проверять отдельно на тестовой Windows.

**Критерий готовности:** не «выглядит рабочим», а UI реально получает события и конечное состояние от независимого процесса, пользователь может скачать диагностику при работающем worker. Непроверенные на Windows пункты явно обозначать как непроверенные.

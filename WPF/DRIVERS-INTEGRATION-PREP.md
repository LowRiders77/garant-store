# Интеграция «Гарант-ПО» в Garant Store

## Решение по текущему этапу

Движок Garant-ПО 6.0 Alpha подключён как локальный драйверный модуль Garant Store. Каталог приложений и его логика WinGet/Microsoft Store сохранены; добавлен самостоятельный раздел «Драйверы» в фирменном стиле.

Для подготовки использован архив `Garant-PO_v6.0.zip` из Library. Архив v5.0 не является актуальным движком для встраивания: там сервер написан на PowerShell и опрашивает состояние; v6.0 содержит многопоточный C#-сервер и SSE.

## Что уже есть в v6.0

- `GarantServer.cs` — локальный HTTP-хост на `HttpListener`, случайный порт на `127.0.0.1`, токен для POST-запросов, SSE `/api/events` и параллельная обработка запросов.
- `Server.ps1` — компиляция C# через `Add-Type` в Windows PowerShell 5.1 и запуск хоста.
- `Worker.ps1` — отдельный процесс сканирования, поиска, загрузки и установки.
- `Core.ps1` — обнаружение устройств Windows и подготовка путей.
- `UI/index.html` — текущий браузерный интерфейс v6.0.
- Поддерживаются Code 28, базовый видеоадаптер, проверка Hardware ID в INF, установка через PnPUtil, отмена, журналы и диагностика.

## Реализовано в интеграционной сборке

- В меню WPF добавлен раздел «Драйверы» с отдельным окном в текущей палитре.
- Сервер и Worker поставляются в `{app}\DriverEngine`; изменяемые файлы находятся в `%ProgramData%\GarantStoreEngine` (только администраторы могут изменять).
- Сервер запускается только при открытии раздела, скрыто, без браузера, с loopback-only адресом и случайным токеном.
- Окно получает начальное состояние и опрашивает локальный `/api/status`; C#-сервер продолжает отдавать SSE для событийного клиента и параллельно обслуживает диагностику.
- Подключены сканирование и установка выбранных устройств с подтверждением, только скачивание, видеоадаптер, проверка сети, установка из папки, отдельная проверка и установка выбранных предложений драйверов Windows Update, отмена, открытие каталога драйверов и выгрузка диагностики.
- При активном Worker окно нельзя закрыть, чтобы операция не осталась без видимого контроля.
- Inno Setup включает исходники двигателя, окно и WPF-адаптер. Windows gate включает изолированный тест сервера с тестовым Worker, который не устанавливает драйверы.

## Что ещё не подтверждено

В исходном `VALIDATION.txt` v6.0 отмечено, что C#-компиляция, запуск на Windows и реальная установка драйверов не были проверены авторами архива. Интеграционная ветка прошла Windows gate: C# компилируется, API проверен, запуск сканирования без поля `Selected` проверен, маршруты поиска/установки Windows Update проверены на тестовом Worker, Setup собран и прошёл install/uninstall. Gate не устанавливает драйверы и не выполняет живой поиск через Windows Update на компьютере пользователя. Для VERIFIED-релиза нужна проверка на тестовом ПК.

В автономном режиме движок может открыть браузер и использовать каталог установки как рабочий. Интегрированный режим отключает браузер и задаёт отдельный каталог данных. Worker устанавливает драйверы системными средствами; модуль запрашивает повышение прав при входе и требует явного подтверждения перед установкой.

## Целевая структура установленной программы

```text
{app}\DriverEngine\
  GarantServer.cs
  Server.ps1
  Worker.ps1
  Updates.ps1
  Core.ps1
  DRP_Known_Links.csv
  Proxy.txt
  UI\index.html

%ProgramData%\GarantStoreEngine\
  State\
  Logs\
  Downloads\
  Drivers\
  Cache\
```

Файлы движка устанавливаются вместе с приложением; изменяемые данные остаются в профиле текущего пользователя. `Server.ps1`, `GarantServer.cs` и `Core.ps1` изменены для отдельного каталога данных, который наследует Worker.

## Контракт WPF-интерфейса с движком

| Задача интерфейса | Контракт v6.0 |
|---|---|
| Проверить запуск движка | `GET /api/health` |
| Получить начальный статус и устройства | `GET /api/status` |
| Обновлять прогресс | `GET /api/events` (SSE), с неперекрывающимся `GET /api/status` как резервом |
| Запустить сканирование и установку отсутствующих драйверов | `POST /api/action`, действия `scan`, `auto`, `download`, `gpu`, `local`, `network`; для адресных операций передавать выбранные `instanceId` |
| Проверить и установить обновления Windows Update | `POST /api/action`, действия `update-scan` и `update-install`; устанавливаются только выбранные `UpdateID`/revision после подтверждения |
| Отменить текущую операцию | `POST /api/cancel` |
| Получить журналы и диагностику | `GET /api/diagnostics`, `/api/report`, `/api/ui-log` |

Случайный порт и токен нужно получать от запущенного экземпляра сервера, не фиксировать в настройках. Все POST-запросы передают `X-Garant-Token`. Ошибки HTTP, потеря SSE и ответы 409 показываются в Garant Store как состояния, а не как успешное завершение.

## Модель запуска и безопасности

1. Раздел «Драйверы» запускает движок только по запросу пользователя; обычный поиск приложений не стартует C#-сервер и Worker.
2. Хост слушает исключительно loopback. При старте не открывает внешний браузер.
3. При открытии раздела «Драйверы» движок запрашивает UAC один раз на сессию; сам Garant Store и его обычный каталог приложений остаются без повышения прав. Сканирование не меняет драйверы. Установка выбранных устройств и обновлений Windows Update требует отдельного подтверждения.
4. Закрытие Garant Store при активной установке блокируется либо предлагает отмену; закрытие окна не должно оставлять незаметный Worker.
5. Статус «проблемных устройств не обнаружено» относится к завершённому сканированию проблемных устройств. Отсутствие предложений Windows Update означает только, что его настроенный источник не предлагает применимых драйверов; это не доказывает актуальность драйверов у каждого OEM.
6. Установка допускается только после проверки архива и точного совпадения Hardware ID в INF. Непроверенные EXE-установщики не запускать.

## Обязательный Windows gate до включения функции

- Компиляция `GarantServer.cs` через Windows PowerShell 5.1 на Windows 10 и 11.
- Установка в `Program Files`, запуск обычным пользователем и проверка записи данных только в `%LOCALAPPDATA%`.
- Проверка, что браузер не открывается и внешний сетевой интерфейс не слушается.
- Запуск/остановка сервера, получение `/api/health`, начального `/api/status` и SSE-событий; проверка отсутствующего поля `Selected`, сканирования и маршрутизации выбранных Windows Update пакетов.
- Сканирование с нулём найденных устройств и отдельный тест на фикстуре из трёх устройств.
- Проверка параллельного чтения статуса и диагностики во время Worker; проверка 409 для второго действия и подтверждённой отмены.
- Проверка UAC-отказа, недоступного DRP/VPN, повреждённого JSON и повторного подключения UI.
- Проверка установки на отдельной тестовой Windows-машине с точкой восстановления: совпавший INF, PnPUtil, повторное сканирование и корректный итог.
- Проверка полного Inno Setup install/uninstall и WPF smoke-test после установки.

## Граница готовности

Раздел и движок включены в интеграционную сборку. До успешного Windows gate и реальной проверки установки не выдавать сборку за VERIFIED-релиз. Каталог приложений сохраняет независимость от состояния Garant-ПО.
